# AI 활용 기술 문서

## 1. AI 활용 개요

PROJECT BRICK WARFARE는 다음 세 종류의 AI 활용을 포함합니다.

1. 플레이어 명령 패턴을 학습하는 적응형 적 지휘 AI
2. 게임 내부에서 실시간으로 작동하는 진영 지휘관 및 자율 외교 AI
3. 기획 구조화, 구현, 타입 검증과 브라우저 테스트 과정에서 사용한 생성형 AI 개발 지원

## 2. 게임 내부 AI 구조

### 2.1 적응형 예측과 기만

Challenge 모드의 `AdaptiveDirector`는 외부 API나 LLM을 호출하지 않고 브라우저 안에서 실행됩니다. 플레이어가 우클릭 명령을 내릴 때 다음 데이터를 갱신합니다.

- 명령 목적지와 가장 가까운 거점
- 명령받은 병과
- 거점별 시간 감쇠 가중치
- 직전 예측 목표와 예측 신뢰도

거점 가중치는 softmax 형태의 확률로 변환되어 HUD에 목표와 신뢰도로 표시됩니다. 신뢰도가 임계값을 넘으면 적월 지휘 AI에 우선 거점을 전달하고, 적월 분대 절반이 해당 거점을 공격하거나 방어합니다.

플레이어가 높은 신뢰도로 예측된 목표와 다른 거점에 새 명령을 내리면 기만 성공으로 판정합니다. 적군의 기존 우선 명령은 잠시 유지되어 실제 전선 공백이 생기고, 플레이어는 점수 보너스를 받습니다.

거점 선호 가중치는 `localStorage`에 저장되어 다음 플레이에서도 초기 성향으로 사용됩니다. 네트워크 연결, 유료 추론 비용, 개인 식별 데이터는 필요하지 않습니다.

### 2.2 진영 지휘관

각 진영은 독립적인 지휘관 상태를 보유합니다. 지휘관은 일정 주기로 다음 정보를 평가합니다.

- 생존 병력 수
- 전차와 항공 전력 비율
- 소유 거점 수
- 진영 고유 교리
- 현재 선택된 전략

평가 결과에 따라 다음 작전 중 하나를 선택합니다.

- 기갑 집중 돌파
- 전진 거점 확보
- 종심 방어
- 항공 우세 확보
- 참호 방어선 구축

선택된 작전은 증원 병과와 유닛의 목표 우선순위에 반영됩니다. 작전 변경 시 판단 이유가 HUD에 표시되므로 플레이어가 AI 의사결정을 확인할 수 있습니다.

### 2.3 유닛 전술 AI

각 유닛은 다음 순서로 행동을 결정합니다.

```text
플레이어 직접 조종 여부 확인
→ 신 모드 명령 확인
→ 외교 관계상 적대 유닛 탐색
→ 유효 사거리 및 선호 교전 거리 계산
→ 공격 또는 접근
→ 표적이 없으면 지휘관 전략에 맞는 거점 선택
```

유닛은 동맹이나 중립 진영을 자동 공격하지 않습니다. 외교 관계가 변경되면 기존 전투 대상도 다시 평가합니다.

### 2.4 자율 외교 AI

외교 시스템은 세 진영의 종합 전력을 비교합니다.

```text
종합 전력 =
생존 유닛 체력
+ 유닛 자산 가치
+ 소유 거점 가치
```

특정 진영이 지나치게 강해지면 약한 두 진영이 동맹을 체결하고 강한 진영을 적대할 가능성이 높아집니다. 전력 균형이 회복되면 동맹 해소, 휴전 또는 거점 분쟁이 발생할 수 있습니다.

모든 외교 관계는 대칭으로 적용됩니다.

## 3. 물리 기반 의사결정

### 장갑과 도탄

피격 방향과 유닛 전방 벡터의 내적을 이용해 전면·측면·후면 장갑 계수를 결정합니다. 입사각이 작고 관통력이 부족하면 도탄으로 처리합니다.

일반탄과 특수탄은 조준 방향의 일정한 속도 벡터를 유지해 직선 비행합니다. AI는 발사 전에 유닛과 표적 사이의 지형 높이를 구간 샘플링하며, 능선이나 산이 사선을 차단하면 발사를 중단하고 표적 방향으로 이동합니다. 보병 외 병과는 일반공격과 긴 재사용 대기시간을 가진 특수공격을 구분하며, 드론의 특수공격은 주변 유닛과 구조물을 파괴하는 자폭으로 처리합니다.

### 항공 역학

- 전투기: 추력, 속도 기반 양력, 받음각, 실속 조건
- 헬기: 지면과의 거리에 따른 지면효과, 고도에서 급하강할 때 와류고리 하강력
- 드론: 헬기보다 높은 측풍 영향 계수

실제 비행 인증용 시뮬레이터가 아니라 게임 플레이를 위한 축약 모델이며, 각 현상의 전술적 차이를 전달하는 데 목적이 있습니다.

### 구조물 붕괴

건물 하단 블록을 지지 블록으로 분류합니다. 생존 지지 블록 비율이 임계값 아래로 내려가면 상부 블록이 연쇄적으로 물리 파편으로 전환됩니다. 큰 붕괴는 주변 유닛에 폭발형 충격 피해를 전달합니다.

### 브릭 폭발과 킬캠

유닛 파괴 시 렌더 모델을 구성하는 메시의 월드 경계 상자를 추출해 서로 다른 크기의 브릭 파편으로 변환합니다. 건물 폭발은 기존 구조 블록과 추가 파편을 방출하며, 폭발 범위의 절차 생성 나무는 인스턴스 행렬을 제거한 뒤 목재·잎 브릭 파편으로 교체합니다.

발사체는 발사 순간 플레이어가 직접 조종했는지 기록합니다. 해당 발사체가 유닛을 파괴하거나 빙의 유닛이 사망하면 킬 이벤트를 만들고, 약 3.35초 동안 시뮬레이션 속도를 낮춰 폭발 지점을 회전 확대 촬영합니다.

### 실시간 지형 제작

기본 지형 함수는 저주파 능선, 세부 굴곡과 강 침식을 합성합니다. God Mode의 산·참호 도구는 클릭 위치에 부드러운 높이 스탬프를 추가하고, 영향을 받는 절차 생성 청크만 다시 구성합니다. 이후 유닛 이동, 발사체 지면 충돌과 새 건물 배치는 변경된 동일 높이 함수를 사용합니다.

## 4. 생성형 AI 활용

### 사용 도구

- OpenAI Codex

### 활용 영역

- 대규모 기획을 브라우저 기술 데모 구조로 분해
- TypeScript 및 Three.js 프로젝트 구조 설계
- 유닛, 탄도, 전투, 절차 지형, 외교 시스템 코드 작성
- TypeScript 컴파일 오류 수정
- Playwright 기반 브라우저 로딩·상호작용·콘솔 오류 검증
- README 및 제출 문서 초안 작성

### 주요 지시 사항

사용자가 제공한 주요 지시의 핵심은 다음과 같습니다.

> 블록 비주얼의 RTS/TPS/FPS 하이브리드 전쟁 게임을 만들고, 신 모드와 모든 유닛 직접 조종, 절차 생성 맵, 거점, 실세계 물리 요소, 블록 파괴, 세 진영 자율 외교를 구현한다.

구현 과정에서 생성형 AI에는 다음 원칙을 추가로 적용했습니다.

- 외부 이미지나 3D 모델 없이 코드 기반 지오메트리를 사용한다.
- 별도의 서버와 유료 API 없이 브라우저에서 실행 가능해야 한다.
- 게임 내부 AI의 판단 근거를 HUD에 노출한다.
- TypeScript strict 모드와 프로덕션 빌드를 통과해야 한다.
- 실제 브라우저에서 시작, 병력 배치, 빙의, 이동, 사격, 신 모드 복귀를 검증한다.

### 검토 및 수정

생성된 코드는 다음 절차로 검토했습니다.

1. `npm run check`로 정적 타입 검사
2. `npm run build`로 프로덕션 빌드 확인
3. Chromium에서 WebGL 렌더링과 HUD 확인
4. 시작 버튼, 병력 배치, 유닛 선택, 직접 조종, 이동, 사격, 복귀 흐름 확인
5. 브라우저 콘솔 및 런타임 예외 확인

## 6. 전장 생성 및 안정성 구조

- 실행 시 산악·참호·시가·삼림·협곡·강변 6개 테마를 무작위로 선택하고 지형 시드, 강 곡선, 수목 밀도, 지형 스탬프, 고층 건물과 장벽 배치를 생성합니다.
- 진영별 7개 초기 스폰 구역과 17개 점령 거점을 사용하며, 진영별 기본 병력을 18기로 제한해 전장 밀집과 렌더링 부하를 줄였습니다.
- 증원은 본부가 아니라 보유 거점에서만 생성되며, 증원 주기마다 거점당 1기씩 최대 18기까지 보충합니다. 거점이 없는 진영은 남은 병력으로 가장 가까운 비소유 거점을 탈환하며, 생존 병력이 0명이 되면 멸망 처리합니다.
- AI 지상군은 적대 진영의 거점 중 최대 3개 전선을 분대 단위로 선택하고, 거점 소유권이 바뀔 때까지 목표를 유지해 제자리 회전과 목표 진동을 방지합니다.
- 거점 안의 생존 유닛 수를 진영별로 비교하고, 단독 최다 진영이 5초 연속 우세를 유지하면 해당 진영이 거점을 점령합니다.
- 거점 소유권이 변경되면 주변 지형 버텍스 색상을 진영색으로 다시 계산합니다.
- 파괴된 유닛은 연출 종료 후 씬, AI 탐색 배열, GPU 지오메트리와 머티리얼에서 제거합니다.
- AI는 표적을 매 프레임 전체 검색하지 않고 유효 표적을 유지하며 일정 주기로만 재탐색합니다.
- 렌더 루프를 최대 60 FPS, AI 이동을 30 Hz, 거점 판정을 10 Hz, HUD 갱신을 5 Hz로 분리해 CPU 갱신 비용을 제한합니다.
- 건물 브릭은 재질별 `InstancedMesh`로 묶고, 발사체 지오메트리를 공유해 파괴 판정을 유지하면서 드로우콜과 객체 생성을 줄였습니다.
- 구조물의 로컬 AABB와 유닛의 이전·현재 위치 사이 선분을 검사해 고속 이동 관통을 방지합니다. 지상 유닛과 드론은 충돌 축을 분리해 벽면을 따라 이동하고, 전투기와 헬기는 구조물 충돌 시 즉시 파괴됩니다.
- 표준 `requestAnimationFrame` 기반 게임 루프와 감시 타이머를 사용해 예상치 못한 렌더 루프 정지를 자동 복구합니다.

## 7. 한계와 향후 개선

현재 버전은 웹 브라우저에서 핵심 개념을 검증하기 위한 기술 데모입니다. 물리 계산은 실제 군사·항공 훈련용 모델이 아니라 플레이 감각과 전술 차이를 위한 축약 모델입니다.

향후에는 공간 분할을 통한 대규모 유닛 최적화, 개별 궤도 접지력, 구조 연결 그래프, 공력 계수 데이터화, 절차 생성 도심과 교량, 저장 가능한 전장 시드 기능을 추가할 예정입니다.
